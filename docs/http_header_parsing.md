# HTTP request-header parsing policy (JS-12)

The parser is implemented in `jestersimple/private/httptransport.nim`.
These rules apply to received HTTP/1.x request headers, not to response
headers generated by application code.

- `Content-Length`, `Transfer-Encoding`, `Host` and supported forwarding fields
  already reject duplicate field lines. Content-Length/Transfer-Encoding
  ambiguity is rejected before normalization.
- Repeated `Connection` lines are combined using a comma and a space. Every
  token is kept; `close` cannot be erased by a later `keep-alive` line.
- Repeated `Cookie` lines are joined with `; `, so `request.cookies` can see
  all the cookies. This is a narrow interoperability allowance, not a reason
  for clients to emit repeated Cookie fields.
- Repeated `Authorization`, `Proxy-Authorization`, `Expect`, `Upgrade`,
  `Origin` and `Content-Type` are rejected with 400 rather than silently
  selecting either the first or last value.
- Other repeated field lines are retained as separate `HttpHeaders` values.
  Code requiring all values must use indexed access or `headers.pairs`;
  ordinary conversion to `string` selects only the first value.
- The raw header-field count limit applies to every received field line,
  including repeated names; the distinct-field limit is separate.
- The request line and each individual header line are limited to 8 KiB;
  an aggregate request-header byte limit also applies. Overlong requests are
  rejected and the connection closed, rather than attempting resynchronization.

The URI reuse test covers the `std/uri.parseUri` behavior used on persistent
connections. Nim 2.2.12 clears the output Uri on every parse; no Jester Simple
parser change was required for this concern.

All test fixtures listen on `127.0.0.1`. No TLS or WebSocket framing is
implemented by these tests.
